# 桌面 AI 工作助手：项目现状与后续开发计划

> 文档版本：v1.0  
> 整理日期：2026-11-05  
> 项目定位：Windows 简体中文桌面 AI 工作助手  
> 核心原则：用户负责工作并主动告知进展，助手负责记忆、整理、恢复上下文和提醒。

---

## 一、产品目标

我们要做的不是普通桌宠、聊天悬浮球或复杂项目管理系统，而是一个极简的桌面项目记忆面板。

打开软件后，用户能快速看到所有项目的状态；进入某个项目后，能立即知道：

- 上次工作做到哪里；
- 已经完成了什么；
- 当前正在处理什么；
- 遇到了什么卡点；
- 下一步应该做什么；
- 有哪些待办、重要决策和历史记录。

用户通过自然语言告诉助手工作进展，AI 自动提取信息并更新项目记录。下次切换回来时，助手能够恢复这个项目的上下文。

### 明确不做的事情

- 不做屏幕监控，不要求持续读取用户屏幕。
- 不做复杂的甘特图、看板或大型项目管理系统。
- 不把桌宠动画、语音、电脑自动操作作为核心功能。
- 不让用户为了维护系统而填写大量表格。
- 不让不同项目的记忆互相混淆。

## 三、当前版本的限制与待验证事项

以下事项必须如实区分：源码中已有相关实现，不代表已经在目标 Windows 电脑上完成验证。

1. Windows 实际运行尚未验证：需要在 Windows 10/11 x64 环境执行安装、启动、退出和重启测试。
2. DeepSeek 联调尚未验证：需要用真实 API Key 测试连通性、模型响应、错误提示和超时处理。
3. 系统托盘和快捷键尚未实机验证：需要测试窗口隐藏、恢复、置顶、快捷键冲突和多屏环境。
4. API Key 安全存在降级情况：如果系统不支持 Electron `safeStorage`，当前程序可能退回本地文件保存，并在界面提示。此时不应在公用账户或不可信设备上使用。
5. AI 整理结果需要人工确认：模型可能误解、遗漏或错误归类内容，重要决策不能未经确认就覆盖。
6. 当前数据结构仍需完善：需要验证异常退出、重复写入、历史记录累积和备份恢复。
7. 项目记忆隔离需要专项测试：必须确认项目 A 的信息不会出现在项目 B 的上下文和 AI 更新中。
8. 自动提醒尚未形成完整闭环：待办字段与真正的系统通知、到期提醒还需要进一步实现和验证。
9. 尚未提供签名安装包和自动更新机制：后续如长期使用，需要考虑安装包签名、版本升级和数据迁移。

## 四、接下来要做的事情

按优先级分阶段推进。先保证数据安全和核心功能可靠，再完善桌面体验，最后考虑扩展能力。

### P0：先完成可用性和数据安全验证

这是下一步的首要任务。

- 在 Windows 10/11 x64 电脑安装 Node.js 20 或更高版本。
- 解压源码，在项目目录执行 `npm install`。
- 执行 `npm start`，确认应用能正常启动。
- 检查界面中文显示、布局和基本交互。
- 创建两个测试项目，分别输入不同内容。
- 关闭并重新打开应用，确认项目数据仍然存在。
- 测试项目切换，确认项目数据和 AI 上下文没有串用。
- 配置 DeepSeek API，验证真实请求和响应。
- 测试 API Key 保存、重启后读取及安全降级提示。
- 测试 AI 返回无效 JSON、网络中断、API Key 错误、额度不足等异常情况。
- 测试导出备份，并验证能否恢复数据。
- 测试系统托盘、窗口置顶和 `Ctrl+Shift+Space` 快捷键。
- 修复测试中发现的问题后，再构建安装包。

P0 验收标准：

- 软件能在目标 Windows 电脑正常启动和关闭。
- 创建的项目和记录在重启后仍然存在。
- 至少两个项目的记录和 AI 更新互相隔离。
- DeepSeek 能正常完成一次进度整理。
- AI 更新失败时，原有数据不会丢失或被错误覆盖。
- 导出的备份文件可用，并能恢复。
- 托盘、快捷键和置顶行为符合预期。

### P1：完善项目记忆能力

这是产品最重要的价值，应优先于增加花哨功能。

- 为每个项目建立独立的长期记忆文件或记录集合。
- 区分项目背景、目标、约束、重要决策、进度、问题和待办。
- 每次 AI 更新都保留原始输入和更新时间。
- 重要决策采用追加历史记录的方式保存，避免被新内容覆盖。
- 对新旧信息冲突给出提示，让用户确认。
- 增加“上次做到哪里了”功能。
- 打开项目时自动生成最近工作摘要。
- 增加项目时间线，按时间查看进展变化。
- 支持用户手动修正 AI 整理结果。
- 支持撤销最近一次错误更新。

P1 验收标准：

- 用户隔几天重新打开项目，能快速了解上次进展。
- 项目历史可追溯，不会只剩一份被反复覆盖的最新摘要。
- AI 能区分事实、计划、推测和待确认信息。
- 用户可以修正 AI 的错误，不会破坏其他历史记录。

## 五、建议采用的核心数据结构

每个项目至少应维护以下信息：

```
{
  "project": {
    "id": "project-id",
    "name": "项目名称",
    "goal": "项目目标",
    "status": "进行中",
    "lastWorkedAt": "最后工作时间",
    "summary": "当前进度摘要",
    "completed": [],
    "inProgress": [],
    "blockers": [],
    "nextSteps": [],
    "todos": [],
    "decisions": [],
    "history": []
  }
}
```

数据设计原则：

- 项目 ID 必须稳定，不能只靠项目名称识别。
- 每个项目的记忆必须独立。
- 历史记录只追加，不因更新摘要而删除。
- AI 生成的修改先校验结构，再写入本地数据。
- 重要内容应保留修改前版本或变更记录。
- 备份文件不应包含 API Key。
- 恢复备份前应提示用户，并避免无提示覆盖现有数据。

## 六、建议的典型使用流程

### 第一次使用

1. 新建项目。
2. 填写项目名称和一句话目标。
3. 在设置中配置 DeepSeek API。
4. 开始正常工作，不需要预先填写复杂表格。

### 日常记录

用户输入：

> 今天完成了首页布局和登录页面，接口联调还差鉴权部分，明天先处理鉴权问题。

AI 应整理为：

- 已完成：首页布局、登录页面。
- 当前卡点：接口联调中的鉴权问题。
- 下一步：处理鉴权并继续接口联调。
- 历史记录：保存用户本次原始输入和更新时间。

AI 更新后，界面展示修改摘要，由用户确认或修正。

### 恢复项目

用户打开项目或输入：

> 上次做到哪里了？

助手展示：

- 项目目标和当前状态。
- 最近一次工作记录。
- 已完成事项。
- 当前卡点。
- 下一步建议。
- 最近的重要决策和待办。

## 九、开发约束与产品原则

后续所有功能决策都遵循以下原则：

1. 简洁优先：界面以最初确认的项目面板为准。
2. 记忆优先：可靠记录和恢复上下文比增加聊天功能更重要。
3. 项目隔离：不同项目的数据、历史和 AI 上下文必须隔离。
4. 本地优先：项目数据默认保存在用户电脑，用户可备份和迁移。
5. 用户可控：AI 可以建议和整理，但重要修改应可检查、可撤销。
6. 不做屏幕监控：所有工作进度以用户主动提供的信息为准。
7. 模型可替换：项目记忆不能绑定某一家模型服务。
8. 不虚报完成度：未在 Windows 实机验证的功能，不标记为已测试或稳定。

最终目标：让用户只需要专注工作、随时告诉助手进展；项目背景、历史、卡点和下一步由助手持续整理和维护。

## 十、v1.2 开发完成记录（2026-11-05 追加）

### 本轮完成的代码范围

P1（项目记忆）、P2（桌面体验）、P3（待办提醒与模型扩展）以及 P4 的工程部分（构建链、版本号、更新日志、CI 修正）已全部实现，并做了 P0 关注的数据安全加固。架构上渲染层重写为 Vue 3（Vite 构建），新增 `src/shared.js` 校验/合并纯逻辑，主进程磁盘写入串行化。详细功能清单见 `CHANGELOG.md`。

要点对照原计划：

| 计划条目 | 实现方式 |
| -------- | -------- |
| AI 修改先校验再写入 | shared.js `validateAiResult`：非法字段拒收/规整，全空拒收，失败明示"原数据未改动" |
| 历史只追加、决策不被覆盖 | `mergeState`：completed/decisions/todos 只追加；卡点/进行中/下一步由 AI 管理但快照留存 |
| 保留原始输入与更新时间 | 每次更新写入 logs：原文、时间、更新前完整快照、AI 摘要、冲突清单 |
| 撤销错误更新 | 「撤销上次更新」按快照恢复并留系统记录 |
| 上次做到哪里 / 打开自动摘要 | 时隔 ≥2 天进入项目自动显示恢复横幅（上次记录 + 卡点/下一步数） |
| 冲突提示用户确认 | 模型输出 conflicts → 预览弹窗警示 → 不自动覆盖 |
| 用户手动修正 | 全部列表支持增/改/删（v2 界面无需填表，修正仅按需） |
| 待办提取 + 到期 + 系统通知 | 预览确认后入待办；每分钟检查到期任务发 Windows 通知（只提醒一次，可关闭） |
| 多模型配置 + 连接测试 | DeepSeek/通义千问/Kimi 预设；设置内测试连接；不支持 response_format 自动降级重试 |
| 备份/恢复闭环 | 导出（不含 Key、记录时间、7 天未备份提醒）；恢复（结构校验 + 自动留档 + 二次确认） |
| 窗口记忆/开机启动/搜索/快捷键自定义/托盘增强 | 均已实现（位置含多屏校验；开机启动默认关闭） |

### 已通过的验证（自动化）

- `npm test`：共享逻辑单元测试 10 用例全过（校验、只追加合并、时间归一、迁移、备份验证）。
